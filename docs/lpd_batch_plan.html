3.2.1 第二份 CSV：lpd_nomatch.csv

當一張圖的四條管線 match 全為 0（亦即 twostep_match + yolo26m_match + yolo26s_match + yolo26n_match == 0）時，將該行同時寫入第二份 CSV lpd_nomatch.csv，方便後續人工檢視 / 重訓資料挑選。

  • 欄位與 lpd_results.csv 完全相同（22 欄）。
  • 同樣採 append-only + per-batch fsync。
  • 斷點續跑判斷只看主 CSV (lpd_results.csv) 的 image_path；lpd_nomatch.csv 只是衍生輸出。
  • 若所有管線皆未偵測到車牌（detected 全為 0），仍視為「四個 no match」，會寫入 lpd_nomatch.csv。

3.3 主流程

1. 啟動：
   a. 載入 4 個 ONNX session（CPU）+ 1 個 PARSeq（GPU 若可用）
   b. 若 lpd_results.csv 存在 → 讀入所有 image_path 至 set (processed)
      否則 → 寫入表頭
   c. 遞迴掃描 LPD，篩出 .jpg/.jpeg/.png，扣除 processed → pending list

2. 分批處理（batch_size = 100）：
   for batch in chunks(pending, 100):
       # 步驟 A：載入此批 100 張原圖入記憶體
       imgs = {path: cv2.imread(path) for path in batch}

       # 步驟 B：對此 100 張，逐管線跑完再切換
       results = defaultdict(dict)
       for pipeline in [twostep, yolo26m, yolo26s, yolo26n]:
           for path, img in imgs.items():
               corners = run_pipeline(pipeline, img)
               if corners is None:
                   results[path][pipeline] = empty
                   continue
               plate_warp = warp_plate(img, corners)         # 400x120
               ocr_raw = parseq_recognize(plate_warp)
               ocr_clean = clean(ocr_raw)                    # 只留 0-9 A-Z
               results[path][pipeline] = (corners, ocr_raw, ocr_clean)

       # 步驟 C：批次原子寫入：累積 100 行 → append 主 CSV → flush + fsync
       append_rows(results_csv, results)
       # 同時把「四欄 match 全為 0」的行 append 到 nomatch CSV
       nomatch_rows = [r for r in results if sum(r.match_cols) == 0]
       if nomatch_rows:
           append_rows(nomatch_csv, nomatch_rows)

3. 中斷恢復：
   未完成的 batch（已讀但未寫入 CSV）下次重跑時會重新處理。
   已寫入 CSV 的 image_path 不會重跑。

3.6 OCR 清洗 + 檔名比對

def clean_text(s: str) -> str:
    return re.sub(r'[^0-9A-Z]', '', s.upper())     # 只留 0-9 A-Z

def expected_from_filename(path: Path) -> str:
    return path.stem.upper()                       # 不去除非字母數字

def is_match(ocr_clean: str, expected: str) -> bool:
    if not ocr_clean or not expected:
        return False
    return ocr_clean in expected                   # 子字串比對
範例：檔名 20241128080042-707175-event-BN2621.jpg
→ expected = "20241128080042-707175-EVENT-BN2621"
→ OCR 清洗結果 "BN2621" 為其子字串 → match = 1

4. 效能設計

  • Session 只載入一次，存在常駐 dict 中。
  • 批次 100：管線切換在 batch 邊界發生，減少 ONNX session warm-up 抖動；圖片 I/O 集中。
  • PARSeq 移到 GPU（若可用），ONNX 偵測仍在 CPU（與 benchmark 一致）。
  • 預估總時間：23,222 張 × 4 管線 ≈ 92,888 次推論。兩步 ~50 ms、YOLOv26 ~70 ms/張、PARSeq ~10 ms/張 → 約 70 分鐘（CPU + GPU mixed）。

5. 中斷續跑保證

  • CSV 採 append + per-batch fsync：每 100 張 flush 一次。
  • 中斷後最壞情況：丟失最後一批未完成的 ≤100 張，重跑時自動補。
  • 每張圖片在 CSV 中只出現一次（用 set 去重）。
  • 不需要額外的 state / checkpoint 檔案。
