用 2×2 結果 fine-tune YOLOv26-pose-n 規劃

來源資料：lpd_results.csv（由 benchmark_lpd_batch.py 產出）
目標模型：yolo26-train-1779339446/best.pt（YOLOv26-pose-n）
訓練框架：Ultralytics 8.4.41（已安裝）
輸出位置：model/yolo26_finetune/ftn_from_2step/weights/best.pt

1. 核心想法：2×2 的哪一格做訓練？

YOLOv26-n matchYOLOv26-n no-match
Two-step match TT
兩者皆對		 TF ⭐ 困難樣本
YOLO-n 的弱點
Two-step no-match FT
YOLO-n 對		 FF
兩者皆錯

各格的訓練價值

  • TF 最有價值 — Two-step 偵測對了（OCR match 暗示 corners 正確），但 YOLOv26-n 偵測失敗。用 Two-step 的 corners 當偽標籤，直接針對性訓練 YOLO-n 的弱點。
  • TT 補強 — 兩者皆對，可補充資料多樣性。但 YOLO-n 已能搞定，邊際效益小。
  • FT / FF 不用 — FT 的 Two-step 結果不可靠（match=0）；FF 兩個都錯，標籤可信度低。要用必須人工校正。
底層邏輯：當清洗後 OCR 是檔名子字串 → 幾乎必然 corners 正確 → corners 可當 pseudo ground-truth。 OCR match 是 corner correctness 的代理指標。

2. 資料準備：CSV → YOLO-pose 標籤

2.1 YOLO-pose 標籤格式

每張圖一個 .txt，所有座標正規化到 0~1（除以影像寬高）：

<class> <cx> <cy> <w> <h> <kpt0_x> <kpt0_y> <vis> <kpt1_x> <kpt1_y> <vis> <kpt2_x> <kpt2_y> <vis> <kpt3_x> <kpt3_y> <vis>
  • class=0（license_plate）
  • vis=2（可見）
  • Keypoint 順序：TL → TR → BR → BL（與現有 yolo_lp/dataset.yaml 一致；sort_corners() 已是這個順序）

2.2 偽標籤生成腳本（建議檔名 make_pseudo_labels.py）

import csv, json
from pathlib import Path
import cv2

OUT_IMAGES = Path("yolo_lp_finetune/images")
OUT_LABELS = Path("yolo_lp_finetune/labels")
OUT_IMAGES.mkdir(parents=True, exist_ok=True)
OUT_LABELS.mkdir(parents=True, exist_ok=True)

with open("lpd_results.csv") as f:
    for row in csv.DictReader(f):
        # 只取 TF: Two-step match=1 且 YOLOv26-n match=0
        if not (row["twostep_match"] == "1" and row["yolo26n_match"] == "0"):
            continue

        img_path = row["image_path"]
        corners = json.loads(row["twostep_corners"])     # [[x,y]*4] 影像座標
        img = cv2.imread(img_path)
        h, w = img.shape[:2]

        # bbox = 4 角點外接矩形
        xs, ys = [p[0] for p in corners], [p[1] for p in corners]
        x1, y1, x2, y2 = min(xs), min(ys), max(xs), max(ys)
        cx, cy = (x1 + x2) / 2 / w, (y1 + y2) / 2 / h
        bw, bh = (x2 - x1) / w, (y2 - y1) / h

        # 4 keypoints 正規化
        kpts = []
        for kx, ky in corners:
            kpts += [kx / w, ky / h, 2]                   # vis=2

        stem = Path(img_path).stem
        label_str = f"0 {cx:.6f} {cy:.6f} {bw:.6f} {bh:.6f} " + \
                    " ".join(f"{v:.6f}" for v in kpts)
        (OUT_LABELS / f"{stem}.txt").write_text(label_str)
        (OUT_IMAGES / Path(img_path).name).symlink_to(img_path)

6. 重要陷阱 / 注意事項

① OCR match 不等同於 corner 像素級完美。
PARSeq 容錯一些角度偏差，所以 Two-step corner 可能只是「夠好讓 OCR 對」而非完美。要更嚴的偽標籤可加篩選：corner 形狀像矩形（內角接近 90°）或長寬比合理（台牌約 3.3:1）。
② 資料分布偏差。
444 張全是 Two-step 強的場景；fine-tune 可能讓 YOLOv26-n 變得「像 Two-step」。建議混入 TT 的隨機 500-1000 張保持資料多樣性。
③ 檔名 → expected 規則的盲點。
EP/ 子目錄檔名是雜湊（無車牌字串），整段會被歸進 FF，但其實兩個模型可能 corners 都對。這些不能進訓練（無法驗證）。
④ 務必留出真正的 hold-out。
別把 lpd_results.csv 的所有資料都拿去訓練/驗證。最好保留一個從未看過的子目錄（例如 0721TW/）做純測試。

7. 建議執行順序

  1. 等主 benchmark 跑完（目前約 21.5%，剩 ~2h）— 取得完整 23,222 張的 CSV，TF 樣本量會更多更具代表性。
  2. 小規模試訓：10 epochs、100 張 TF 樣本，驗證 pipeline 通暢、label 格式無誤。
  3. 全量訓練：完整 TF + TT 混合資料、50 epochs、留 20% 驗證集。
  4. 驗證：先用 yolo pose val 看 mAP；再用 benchmark_lpd_batch.py 與舊模型同場比較 TF 是否縮小。
  5. 迭代：若仍有 TF，再把新模型的 TF 拿去 fine-tune 第二輪（active learning）。

本規劃假設 lpd_results.csv 已產出。可隨 benchmark 進度動態更新可用 TF 樣本數。
